# `assets/` — layout conventions

A convention, not a gate. The loaders already refuse paths that leave `assets/`
or reach into `wip/`; everything else below is what to follow when adding or
renaming art, and what to bring the rest of the tree back to when something
drifts. Break it when there is a reason, and say the reason in that folder's
README.

## What lives here

**Only what the shipped game can load.** The whole folder (minus `wip/`) is
copied next to the exe on every build, so anything here ships.

| Where | What |
|---|---|
| `scenes.txt`, `sprites.txt` | The manifests. A file nothing in them (or in a `backdrop.txt`) reaches is either a draft or dead. |
| `palette.gpl` | Generated by `tools/export_palette_gpl.py` for painting tools. |
| `<stem>.bmp` at the root | Sprites and props bound in `sprites.txt` (`player_sheet`, `tree_*`). Flat, bare stems: props name them as `<stem>` and cannot take a path. |
| `<set>/` | One backdrop set per folder; see below. |
| `wip/` | Drafts, candidates, superseded art. Never staged, never loadable. See `wip/README.md`. |

**Not here:** test fixtures go in `tests/fixtures/` (tests run from the source
root, so they load `tests/fixtures/...` directly; tools write there via
`pixel_art.fixture_path`). Source art and previews go in `art_src/`.

## Backdrop sets: `assets/<set>/`

```
<set>/
  README.md              what the set is, how it was made, its layer table
  backdrop.txt           the layer manifest
  <set>_NN_<name>.bmp    parallax layers
  <set>_material.bmp     terrain material map   (if the scene has terrain)
  <set>_albedo.bmp       terrain colour map     (if the scene has terrain)
  <set>_level.txt        level file             (optional)
```

- **Name:** `bg_<place>`; a bigger cut of an existing place is
  `bg_<place>_wide`. Every file inside repeats the full set name as its prefix,
  so a stray BMP still says where it belongs.
- **Layer numbers run front to back:** `01` is the foreground, the highest
  number is the sky. Two digits, contiguous, no gaps.
- **Every file in the folder is referenced** by `backdrop.txt` or `scenes.txt`
  (READMEs aside). A layer that was cut goes to `wip/` or is deleted.
- **Generated sets name their generator** (`tools/generate_<set>.py`) in the
  README, and the generator is named after the set.

## Adding or renaming something

1. Put it in the right place above; keep drafts in `wip/` until they win.
2. Reference it from a manifest in the same change.
3. Renaming: rename the folder, every prefixed file, the generator, and grep
   the repo (`src/`, `tests/`, `tools/`, READMEs) for the old name.
